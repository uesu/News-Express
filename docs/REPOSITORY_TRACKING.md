## 5. Runtime state, retention, and privacy boundaries

| File | Created when | Contents | Retention/owner |
|---|---|---|---|
| `posted_tweets.json` | X monitor runs | account/tweet dedup keys | newest keys per account plus global backstop; repository operator owns it |
| `posted_reddit.json` | Reddit monitor runs | subreddit/post dedup keys | newest keys per subreddit plus global backstop; repository operator owns it |
| `pending_reddit.json` | Reddit has a transient/held post | first/last check timestamps, reason, and additive audit fields | pruned at the 48-hour posting window |
| `proxy_health.json` | Reddit V3 proxy warm-up runs | per-service warm-up result and timestamp | overwritten only when health changes; repository operator owns it |
| `posted_messages.json` | only when `RETRACT_DEAD_POSTS=1` | Reddit path/subreddit, Discord message ID, delivery/publish timestamps, and the public card payload | candidates are pruned after `RETRACT_WINDOW_SECONDS`; retracted entries are removed |

These records do not collect Discord member data. The conditional retraction record exists because Discord requires the message ID for a later edit/delete; it is not enabled by default. A public repository makes any committed state visible to repository readers, so operators should use a private repository if their operational state should not be public.

The Privacy Policy is the detailed recipient disclosure, including Reddit/X mirrors, media CDNs, proxy services, Discord, GitHub Actions, optional Discohook, and cron-job.org. The Terms of Service remains the acceptable-use and operator-responsibility document. Both were re-read and updated for the conditional retraction record rather than being given an artificial behavior claim.
